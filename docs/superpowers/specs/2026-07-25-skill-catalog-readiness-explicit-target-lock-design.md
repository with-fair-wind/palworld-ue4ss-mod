# 技能目录就绪门控与显式帕鲁锁定设计

## 背景

PalworldEditor v1.4.4 已能在用户手动点击“刷新技能列表”后加载主动、被动技能，
并完成新增、替换、删除和清空。但游戏刚进入存档时仍有两个时序问题：

- mod 在 `on_update()` 的首批更新中自动加载一次技能目录。此时
  `PalPassiveSkillManager`、本地化 World Context 或 `PalUIUtility` 依赖可能尚未就绪。
  主动技能的编译期 Raw ID 表仍会被标记为可选择，导致界面在游戏技能子系统尚未就绪时
  允许提交写入，游戏可能崩溃。
- 当前目标解析偶尔在单帧内找不到本地 `Otomo Holder`。现有
  `SelectedTargetState::invalidate_if_changed()` 把“解析失败”和“解析到不同 GUID”
  都当成目标变化，因此即使用户没有按数字键切换帕鲁，也会清除选择并显示
  “当前帕鲁已变化”。

UE4SS 日志已经确认第二个问题：同一个草莽猪保持高亮期间，目标解析状态会在成功和
瞬时失败之间切换，随后恢复为相同 GUID。

## 目标

- 技能目录在游戏运行时依赖真正就绪前保持只读，所有技能写入入口均不可点击；
- 启动后自动低频重试完整技能目录加载，用户不必依赖手动刷新才能进入安全状态；
- “刷新技能列表”继续作为立即、完整重新加载主动技能、被动技能和当前语言名称的入口；
- 用户点击“选择当前帕鲁”后锁定该目标，数字键变化或瞬时解析失败都不自动替换或清除它；
- 只有再次点击“选择当前帕鲁”才更新锁定目标和技能快照；
- 锁定目标与当前高亮目标不一致或暂时无法确认时禁止写入，避免修改错误对象；
- 保留现有 GUID、目标代数和执行前重校验，不缓存跨帧 `UObject*`。

目标版本为 PalworldEditor v1.4.5。

## 采用方案

### 技能目录运行时就绪状态

在 `SkillCatalogSnapshot` 中增加独立于目录内容的 `runtimeReady`：

```cpp
struct SkillCatalogSnapshot
{
    SkillCatalogSection passive;
    SkillCatalogSection active;
    bool runtimeReady{};
};
```

`ready` 继续表示某一类目录已有可展示的选项；`runtimeReady` 表示本轮加载同时验证了：

- 被动技能管理器和 `GetPalAssignablePassiveIDs` 可用；
- 被动目录非空；
- 主动技能定义表非空；
- 本地化 World Context、`PalUIUtility` 和两类名称函数可用；
- 主动、被动目录都至少取得了一个当前游戏语言名称。

启动阶段即使主动 Raw ID 表已经建立，只要 `runtimeReady == false`，界面仍只读。
一旦完整加载成功，后续目录刷新暂时失败可保留上一份目录和已经验证过的运行时就绪状态；
返回主菜单或重新载入 mod 不在本次改动范围内。

### 自动重试

增加一个不依赖 Unreal 的 `SkillCatalogRefreshScheduler`，以
`std::chrono::steady_clock::time_point` 决定是否刷新：

- 首次 `on_update()` 立即尝试；
- 未就绪时每两秒最多自动尝试一次；
- 已就绪时停止自动重试；
- 用户点击“刷新技能列表”时忽略等待间隔并立即刷新；
- 每次反射加载仍只在游戏线程执行。

两秒间隔避免在启动加载阶段每帧遍历约 390 个主动技能并调用本地化函数。

### 显式锁定目标

`SelectedTargetState` 只在用户成功点击“选择当前帕鲁”时调用 `confirm()`。
持续解析结果仅用于计算当前是否可以安全编辑，不再自动改变选择：

```text
未选择目标
  -> 点击选择且解析成功
  -> 锁定 GUID、名称、技能快照

已锁定目标 + 当前解析为相同 GUID
  -> 允许编辑

已锁定目标 + 当前解析失败
  -> 保留锁定目标，暂停编辑

已锁定目标 + 当前解析为不同 GUID
  -> 保留锁定目标，提示重新选择，暂停编辑

再次点击选择且解析成功
  -> 锁定新的 GUID、递增代数、重读技能快照
```

点击选择但当前解析失败时保留旧锁定目标，只显示失败原因；不会用空观察结果清除它。

### 执行前安全检查

GUI 只有同时满足以下条件才开放新增、替换、删除和清空：

- 已显式选择目标；
- 当前帧成功解析到与锁定 GUID 相同的帕鲁；
- 技能目录 `runtimeReady`；
- 没有待处理请求。

游戏线程消费请求时继续调用 `apply_if_target_is_current()` 重校验目标代数和 GUID。
如果请求到达时目标不同或暂时无法解析，拒绝本次请求但保留锁定目标和技能快照，
提示用户恢复原高亮或再次点击“选择当前帕鲁”。绝不猜测目标，也不执行延迟写入。

## GUI 行为

- 目录未就绪时显示“技能目录正在等待游戏初始化，将自动重试”，并禁用所有修改按钮；
- 锁定目标仍显示在“当前已选择帕鲁”一行；
- 当前高亮目标不同或解析失败时显示安全提示，但不再显示“当前帕鲁已变化”；
- 点击“选择当前帕鲁”成功后才切换到新帕鲁并重置正在编辑的选择框；
- 手动刷新成功后立即更新当前语言名称；
- 当前已装备技能在只读阶段仍可显示 Raw ID 或已有标签。

## 组件变更

### `inc/skills/skill_catalog.hpp`

- 为完整目录增加运行时就绪状态；
- 增加自动刷新调度器；
- 保持主动、被动区段的独立回退；
- 增加完整目录是否允许写入的纯值判断。

### `inc/skills/selected_target_state.hpp`

- 删除“观察失败或不同就自动失效”的行为；
- 增加锁定目标与当前观察是否一致的查询；
- 保持 `confirm()`、代数和执行前匹配校验。

### `src/pal_skills.cpp`

- 在目录加载时明确计算 `runtimeReady`；
- Raw ID 目录可继续用于展示，但不把部分加载误认为可安全写入。

### `src/dllmain.cpp`

- 用调度器驱动启动自动重试和手动刷新；
- 不再根据持续观察自动调用 `invalidate()`；
- 在快照中发布“当前观察与锁定目标一致”状态；
- 所有技能修改按钮统一使用写入门控；
- 请求重校验失败时保留选择。

### 测试与文档

- 纯 C++ 测试覆盖自动刷新节流、手动立即刷新和成功后停止重试；
- 覆盖不同 GUID、空观察都不改变锁定目标；
- 覆盖只有相同 GUID 才允许编辑；
- 覆盖部分目录不能进入运行时就绪状态；
- 更新版本和用户说明为 v1.4.5。

## 非目标

- 不缓存帕鲁参数对象或 Holder；
- 不在解析失败时自动等待并执行已经提交的技能修改；
- 不修改主动/被动技能的实际反射写入协议；
- 不增加 DataTable、外部 JSON 或网络依赖；
- 不把数字键切换重新定义为自动选择编辑目标。
