# PalworldEditor 动态功能开关、安全性与帧时间重构设计

**日期：** 2026-07-29  
**适用基线：** PalworldEditor 1.6.7、Palworld 1.0.1、UE4SS Experimental  
**范围：** 爪钩枪无冷却、同公会跨据点制作与建造材料共享

## 背景与已确认根因

当前两个功能都已经在 UE4SS GUI 中提供复选框，但复选框同时读写 `config.ini`。持久化本身不是掉帧来源，
问题来自功能在世界生命周期中的应用时机，以及资源联合暴露了重复的消费路径。

### 爪钩枪无冷却

启动配置要求开启时，现有状态机会在世界刚可访问后执行一次
`FindAllOf("PalWeaponBase")`。如果正式爪钩对象尚未生成，网关返回“目标不可用”，但账本仍把本世界标记为
已经尝试，后续不会自动再次应用。用户关闭再开启会重置该标记，因此进入存档后重新切换才生效。

### 据点资源共享

当前制作会话要求扩展玩家 `InventoryMultiHelper`，建造会话要求同时扩展据点仓储模块和玩家 Helper。
会话表允许建造与制作重叠，并把两者的联合目标合并。用户先按 `B`、再打开制作设施时，日志明确出现：

```text
modules=true, helper=true
```

游戏内复现进一步证明远端材料被重复统计。蔬菜蛋糕场景中，本地有 2 个蛋、远端实际有 30 个蛋，预览显示
62 个：

```text
2 + 30 × 2 = 62
```

配方每份消耗 8 个蛋，因此预览给出 7 份，实际材料只能完成：

```text
(2 + 30) / 8 = 4
```

同时，当前向所有据点模块和玩家 Helper 建立联合的日志耗时约 77–106 ms，是打开建筑菜单时可感知帧尖峰的
直接来源。制作 Helper 单入口的联合日志约为 0.08–0.11 ms，说明全模块扩展和通知是主要高成本路径。

## 目标

- 两个功能只通过游戏内 GUI 动态控制，不再使用配置文件保存偏好。
- 每次启动 Mod 时两个功能默认关闭；用户选择在当前游戏进程内保持。
- 切换世界前安全恢复旧世界状态；新世界通过各自安全门后按用户当前意图重新应用。
- 爪钩目标晚于世界就绪生成时，不要求用户关闭再开启，也不引入逐帧全局对象扫描。
- 制作与建造预览、资格判断和真实扣除使用唯一且一致的容器集合。
- 每个容器 GUID 在一个消费视图中最多出现一次。
- 关闭状态零功能 Hook、零对象扫描、零资源校准和零写入。
- 开启后的空闲状态不产生持续掉帧或周期性高成本扫描。
- 保持单人世界/本地房主限定；任何不支持、过期或无法验证的状态都安全回退原版行为。
- 使用现代 C++23、清晰模块边界、纯值状态机和可独立测试的领域逻辑。

## 非目标

- 不支持远程客户端或专用服务器。
- 不实现修理、医疗、自动生产、运输、箱子 UI 或其他材料场景共享。
- 不直接修改物品槽、`StackCount`、存档文件或原版资格函数返回值。
- 不实现世界存续期永久联合。
- 不引入后台线程、逐帧 UObject 扫描或版本绑定的机器码 Detour。
- 不为统一命名而重构与本次功能无关的既有代码。
- 不承诺第三方资源共享 Mod 同时启用时的兼容性。

## 方案选择

### 采用：纯游戏内动态开关

两个功能每次进程启动默认关闭，GUI 修改的用户意图仅存于内存。配置文件不再读取或写入；旧
`config.ini` 可以留在磁盘，但 Mod 忽略其内容。

优点：

- 主菜单、冷启动和用户未授权时不执行实验性功能。
- 用户可在异常发生时立即关闭并恢复原版状态。
- 不会因为上次保存的开启状态在新世界对象尚未生成时过早应用。
- 能明确测量关闭、开启空闲和活动操作三种性能状态。

代价是每次启动游戏都需要重新开启。该取舍符合两个功能仍需 Palworld 版本内游戏验证的现状。

### 未采用：动态开关加配置持久化

这是现有方案，使用方便，但会在下一次启动自动开启。即使增加安全门，用户也无法在冷启动前明确撤销上次的
实验性功能意图，不符合本轮“默认零工作、失败安全”的优先级。

### 未采用：仅配置文件

该方案不能在游戏内即时恢复原版行为，调试和异常处置成本最高。

## 总体架构

### GUI 与游戏线程边界

GUI 线程只写入标准库纯值请求：

- 用户期望开启或关闭；
- 用户请求重新应用；
- 对应请求的世界代次。

游戏线程在 EngineTick 消费请求。所有 UObject 查找、反射、Hook 注册、数组修改、属性写入、重读和恢复都只在
游戏线程执行。GUI 只读取不可变快照，快照包含：

- 用户期望状态；
- 实际运行状态；
- 当前世界代次；
- 等待的安全门；
- 最近一次结果和错误；
- 是否因恢复失败而安全停用。

### 统一运行状态

使用不依赖 Unreal 的纯值状态机表达每个功能的生命周期：

```text
off
  -> waitingForWorld
  -> waitingForReadiness
  -> applying
  -> active
  -> restoring
  -> off

任意预检失败 -> unavailable（保持原版）
恢复验证失败 -> safetyDisabled（本世界不可重新开启）
```

用户意图在同一进程内跨世界保留，但活动对象、Hook、资源会话和恢复账本不跨世界复用。

### 世界切换顺序

LoadMap 前置回调执行：

1. 拒绝新的功能请求；
2. 恢复活动爪钩冷却覆盖；
3. 结束材料操作并恢复资源联合；
4. 验证恢复结果；
5. 注销世界相关功能 Hook；
6. 递增世界代次并清空旧请求、目录和状态。

LoadMap 后置回调只恢复“可等待”能力。实际应用必须等各自安全门通过，不在回调内直接扫描或修改游戏对象。

析构函数不访问 Unreal。Hook 和覆盖必须在游戏线程关闭流程中显式清理；热卸载前 GUI 必须处于已关闭或已安全
恢复状态。
> **已过时（superseded）**：热卸载由卸载线程请求游戏线程执行有界清理（立即一次、失败后每 2 秒、最多
> 5 次），卸载请求发出后 GUI tab 与 LoadMap 回调立即钝化，无需预先关闭 GUI；见 AGENTS.md 热重载契约。

## 爪钩枪无冷却设计

### 目标发现与应用

继续使用经过游戏验证的 `PalWeaponBase.CoolDownTime` 覆盖路径，并通过
`ownItemID.StaticId` 精确白名单识别正式爪钩枪。不得退化为修改全部 `PalWeaponBase`。

开启后的执行顺序：

1. 等待世界可访问、本地玩家、Common 主背包和本地装备系统安全门；
2. 优先通过本地装备链确认已装备武器已经生成；
3. 安全门通过后才执行一次严格目标扫描和事务式覆盖；
4. 保存每个实际修改对象的完整对象名与原始冷却值；
5. 写入后立即重读验证。

如果当前 UHT 中不存在稳定的本地装备就绪接口，不允许用逐帧 `FindAllOf` 代替。此时只允许：

- 世界安全门通过后的一次扫描；
- 已确认的装备变化事件触发的一次扫描；
- 用户点击“重试应用”触发的一次扫描。

“目标尚未生成”是可重试状态，不设置终止性的 `applyAttempted`。布局缺失、目标身份不确定和写后验证失败是
终止性错误，保持原版并在 GUI 报告。

### 恢复

关闭开关和 LoadMap 前只恢复本 Mod 实际覆盖且当前值仍等于 Mod 覆盖值的对象。对象已经销毁时不重新创建；
对象仍存在但身份、字段或当前值不匹配时拒绝盲写。

恢复成功后清空账本。恢复无法完整确认时，本世界进入 `safetyDisabled`，防止反复切换累积不可恢复写入。

### 帧时间约束

- 默认关闭或已成功应用时，EngineTick 为常量时间状态判断。
- 不注册射击或冷却高频 Hook。
- 不使用定时全局扫描。
- 每个明确触发最多执行一次目标扫描；扫描耗时必须记录并纳入游戏内性能验证。

## 据点资源共享设计

### 纯值目录

开启并通过本地房主安全门后，使用现有管理器 API 建立同公会据点、仓储模块和普通箱子的纯值目录。目录按容器
GUID 去重并保持稳定顺序，不保存 UObject、属性或数组地址。

目录初次准备完成前，GUI 显示“正在准备”，菜单保持原版行为。不得在原版首次资格判断完成后才异步追加联合，
否则会重现首次图标灰色或首次配方不可用。

结构事件只设置合并失效标志。无活动材料会话时，下一次安全 EngineTick 执行一次目录校准；活动会话期间不
校准、不拆装联合。60 秒校准仅作为遗漏事件的空闲兜底。已登记但暂未解析到活动 ConcreteModel 的普通箱子
不得使整次目录失败；已加载部分立即发布为可用目录，未加载部分排除并按 1、2、4 秒指数退避、最高 30 秒重试。
结构性反射或权限错误不做每秒重试，只等待显式失效事件或 60 秒兜底。

### 单前台操作协调器

现有“多个会话合并联合目标”改为“单前台操作拥有者”：

- 同一时刻只有一个制作或建造操作可以拥有实时联合；
- 新操作到来时先阻止旧操作继续访问，恢复并验证旧联合，再建立新联合；
- 建造切换到制作时不得保留任何建造模块注入；
- 制作切换回建造时重新按建造配置获取；
- LoadMap、关闭开关和世界代次变化强制结束拥有者。

该协调器使用固定大小纯值状态，不在高频 Hook 中分配内存。

### 按消费者分离的联合配置

资源联合不再用一个 `{baseModules, playerHelper}` 布尔组合覆盖所有场景，而是使用显式操作阶段：

- 制作预览与制作请求：唯一的玩家 Helper 入口；
- 建造菜单资格：只使用经游戏验证的建造预览入口；
- 建造提交与扣除：只使用当前目标据点所需的消费入口；
- 操作阶段变化时至多执行一次配置切换，禁止在列表和资格高频 Hook 中反复修改数组。

同一个活动配置中，同一容器 GUID 只能出现在一个会被该消费者汇总的入口。建造不得再把远端箱子追加到全部
同公会据点模块；只允许扩展当前目标据点所需的最小入口。

每次原版数组通知后必须重新读取相关序列，再按 GUID 和注入次数验证最终重数。发现重复、部分注入或不可确认的
原版传播时立即按本次账本回滚，保持原版行为。

### 制作生命周期

制作联合必须在 `PalUIConvertItemModel:Initialize` 的原版首次资格计算前可用。配方选择、最大数量和
`CanStartProduction` 高频路径只触碰现有会话。

`StartProduction` post-hook 不再立即释放联合；它只记录“请求已提交”并刷新制作会话。制作联合最早在最后一次
制作活动后的空闲租约到期时恢复；LoadMap、关闭开关和前台操作切换可以更早强制恢复。空闲阈值沿用 1.5 秒，
但游戏内必须验证真实扣料已在该窗口内完成；验证失败时需要改用已确认的原版完成事件，不能扩大为永久联合。

### 建造生命周期

建造联合必须在原版建筑菜单首次资格计算前建立。当前目标据点无法稳定确认时，不建立全据点联合，菜单保持原版
行为并提示原因。

建筑菜单 `Setup` 完成后，只向当前建造模型发送一次原生 `OnUpdateInventory(Container)` 事件，使首次资格缓存
重算。不得重复调用 Helper 的 `OnRep_Containers`，也不得增加逐物品或逐帧刷新 Hook。

退出建造模式释放建造会话。即使原版退出事件遗漏，新的制作操作也会通过单前台协调器抢占并恢复建造联合，
从而消除“按 B 后制作翻倍”的故障。

### 恢复账本

账本只保存：

- 世界代次；
- 对象完整名称；
- 原始 GUID 序列；
- 本次注入的 GUID 与次数；
- 当前联合配置和目标据点 GUID。

恢复按注入次数删除本 Mod 添加项，同时保留会话期间原版新增的非注入引用。恢复后重新读取并确认没有遗留项。
任何对象失效、序列无法读取或注入次数不完整都停止后续联合并进入本世界安全停用。

## 性能契约

### 关闭状态

- 不注册爪钩或资源功能 Hook；
- 不执行资源目录调度；
- 不扫描 UObject；
- 不创建每帧字符串或容器快照；
- EngineTick 只进行固定数量原子/状态判断。

### 开启空闲状态

- 爪钩成功应用后无常驻扫描和写入；
- 资源目录只响应合并后的结构失效，60 秒校准为空闲兜底；
- 暂未加载容器只触发有上限的指数退避，不阻塞已加载容器；
- 活动材料会话期间不校准目录；
- Verbose 日志只记录低频状态转换、目录校准、联合建立和恢复耗时。

### 活动操作

- 配方、建筑列表和资格高频 Hook 只更新固定大小状态；
- 高频 Hook 不执行 UObject 查找、反射、数组修改、目录发现、日志或动态字符串构造；
- 制作只修改一个 Helper；
- 建造只修改当前目标据点所需入口；
- 不再创建 `modules=true, helper=true` 的跨操作合并联合。

### 游戏内性能验收目标

- 目录校准记录最近、最近成功和本世界峰值耗时以及尝试次数；常规目标低于 1 ms。
- 制作 Helper 联合低于 1 ms；当前日志基线约 0.08–0.11 ms。
- 建造联合不超过一个 60 FPS 帧预算，即 16.7 ms。
- Mod 加载但两个开关关闭时，帧时间与未启用这两个功能的基线无可重复差异。
- 开启后空闲至少 10 分钟，不出现 Mod 引入的周期性帧尖峰或重复联合日志。
- 若建造联合仍稳定超过 16.7 ms，功能不能判定完成，必须继续缩小入口、删除冗余通知或调整安全预备阶段。

这些是发布门，不是对所有硬件和第三方 Mod 环境的绝对帧率承诺。

## 错误处理与崩溃防护

- 每个请求携带世界代次；代次不匹配时零写入。
- 所有反射写入先完整预检对象、类型、属性、函数和权限。
- 写入后立即重读；失败时事务回滚。
- Hook 只有在必需路径全部解析后注册；缺失路径只禁用对应能力。
- 自己触发的数组通知由重入保护抑制，不能重新调度目录或再次建立联合。
- 任何异常均不得伪造成功返回值或手动扣料。
- 恢复失败后不能通过关闭再开启绕过安全停用。
- 不在析构、GUI、后台线程或世界不可访问阶段调用 Unreal。

UE4SS、PalSchema 和 Palworld 反射布局具有版本相关性，因此无法诚实承诺所有运行环境绝对零崩溃。本设计的
安全目标是：对已知生命周期、对象失效、重复数组、恢复失败和版本不匹配路径进行预检和失败关闭，使其保持
原版行为而不是继续执行不确定写入。

## 模块化与现代 C++ 约束

### 模块边界

`dllmain.cpp` 只负责 Mod 生命周期、全局回调和模块调度。具体业务拆分为：

- 通用纯值运行状态与 GUI 命令/快照；
- 爪钩纯值状态机与恢复账本；
- 爪钩 Palworld 反射网关；
- 资源目录与校准调度器；
- 单前台材料操作协调器；
- 操作阶段和消费者联合配置；
- 可逆资源注入/恢复账本；
- 资源 Hook 与 Palworld 反射适配层；
- GUI 渲染适配。

Palworld 1.0.1 的 UFunction 路径集中在版本化 Hook 清单，不散落在领域逻辑中。未来新增材料操作时，通过新增
操作/阶段配置和薄适配器扩展，不修改制作与建造的核心状态转换。

### C++23 规范

- 使用强类型 `enum class`、值语义、`std::span`、`std::optional` 和明确的结构化结果。
- STL 所有权采用 RAII 和 `std::unique_ptr`；裸 Unreal 指针仅是当次游戏线程调用内的非拥有句柄。
- 纯值状态机和析构尽量 `noexcept`；异常不得穿过 UE4SS Hook 或 DLL 边界。
- 高频路径使用固定大小数组和预分配容器，避免每帧堆分配与完整快照复制。
- 使用 `const`、范围算法和明确输入输出，不引入隐式拥有关系、布尔参数组合或新的全局可变状态。
- Hook 拥有者提供显式游戏线程关闭流程；析构不得隐式触发 Unreal 调用。
- 遵循仓库 `.clang-format`、`.clang-tidy`、C++ Core Guidelines 和现有局部命名风格。
- 不进行与本次目标无关的大范围重命名或抽象；优先组合、值类型和数据驱动清单，避免不必要的虚继承层。

## 测试与验收

### 纯 C++ 测试

- 两个功能默认关闭且没有任何待执行工作。
- 动态开启、关闭、重复切换和世界代次变化的状态转换。
- 爪钩首次目标不可用后保持可重试，终止性错误不会无限重试。
- 爪钩原值账本、幂等应用、关闭恢复和恢复失败安全停用。
- 单前台材料协调器不允许制作与建造同时持有联合。
- 新操作抢占旧操作时先恢复、后应用。
- 资源目录按公会、容器类型和 GUID 去重。
- 本地 2 个蛋加远端 30 个蛋的有效总量为 32，不是 62。
- 联合通知后的重数检查能拒绝重复和部分注入。
- 制作提交不会立即释放会话，空闲到期后只恢复一次。
- 错误世界代次、关闭和 LoadMap 清空全部待处理工作。

## 完成标准

只有同时满足以下条件，两个功能才可标记为完成：

- 纯动态开关和世界生命周期行为符合本设计；
- 已确认的爪钩首次应用失败与资源双重计数故障均通过回归测试；
- 所有本地构建和测试通过；
- 游戏内功能测试覆盖预览、实际扣除、关闭恢复和多次 LoadMap；
- 性能日志达到本设计预算，且基线对比不存在可重复持续掉帧；
- 文档、GUI 状态和实现保持一致。
