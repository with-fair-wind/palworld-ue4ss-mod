# PalworldEditor 可扩展材料操作会话与早期原版判定设计

## 背景与根因

PalworldEditor 1.6.0 已经把同公会据点普通仓储临时联合到 Palworld 原生资源容器关系中。游戏内验证表明：

- 原版建筑菜单能够显示其他据点材料形成的合计数量；
- 临时联合能够建立和恢复；
- 资源功能不再执行旧版逐秒全局 UObject、箱子槽位扫描。

但是，建筑图标仍可能被判定为不可选。根因不是资源联合内容错误，而是建立时序太晚：

- 建造联合主要在 `PalBuilderComponent:ChangeMode` 的 post-hook 或
  `PalBuilderComponent:IsExistsMaterialForBuildObject` 的 pre-hook 中建立；
- 原版建筑菜单可能在这些入口之前就完成建筑列表和可用状态计算；
- 制作联合在 `PalUIConvertItemModel:Initialize` 的 post-hook 中建立，同样无法保证初始化期间的配方数量与
  可制作状态读取到联合后的容器。

因此会出现“材料数量已经共享，但原版资格缓存仍然不可用”的不一致。修复必须让资源联合在原版菜单首次资格
计算之前存在，而不是修改图标状态或强制改写原版函数返回值。

## 目标

- 原版建筑菜单在首次生成建筑列表和可用状态前看到同公会跨据点资源。
- 原版工作台与流水线在初始化、配方选择、最大制作量计算和开始制作前看到相同资源联合。
- 预览、资格判断和真实扣料始终交给 Palworld 原生逻辑。
- 建筑和制作共用一份实时资源联合；重叠操作只建立一次，最后一个操作结束后只恢复一次。
- 高频菜单与预览 Hook 只执行固定大小的纯状态更新，不发现据点、不解析对象、不修改容器数组。
- 共享关闭或没有材料操作会话时，不产生常驻逐帧反射和资源数组修改。
- 把建筑和制作改造成数据驱动的材料操作配置，后续可以增加其他材料消耗场景而不重写资源池核心。
- 保持单人世界/本地房主安全门、同公会过滤、普通仓储范围和可逆恢复语义。

## 非目标

- 本轮不实现修理、科技研究、帕鲁强化、物品升级或其他材料操作。
- 不支持远程客户端或专用服务器。
- 不处理其他 mod 增加的“创建蓝图”等界面和请求路径。
- 不伪造建筑图标、配方可用状态、最大制作数量或请求成功返回值。
- 不移动物品，不直接写 `ItemSlotArray`、`StackCount` 或存档。
- 不恢复逐秒槽位聚合、全局 `FindAllOf` 扫描或永久资源联合。
- 不承诺所有硬件和任意箱子数量下绝对没有单次耗时波动；性能契约是消除常驻、周期性活跃会话重建和高频
  回调中的重型工作。

## 方案比较

### 方案 A：在原版早期入口建立操作会话和原生资源联合

在建筑菜单打开和制作模型初始化的 pre-hook 中建立资源联合，让原函数第一次执行时就读取联合后的原生容器。
列表刷新、配方选择和最大数量计算等高频入口只刷新租约。

优点：

- 预览、资格判断和真实扣料使用同一原生数据来源；
- 不需要猜测或改写不同 UI 层的缓存和返回值；
- 联合生命周期仍限定在玩家主动材料操作期间；
- 可以抽象成通用操作会话，便于以后扩展。

缺点：

- 依赖 Palworld 1.0.1 UFunction 入口和调用顺序，必须进行游戏内验证；
- 目录尚未就绪时必须安全回退，不能为了第一次打开菜单同步执行无界扫描。

### 方案 B：共享开启后永久维持联合

世界就绪后建立联合，直到关闭功能或切换世界。

优点是所有菜单都会天然看到共享资源。缺点是普通箱子 UI、自动生产、运输等非目标系统也可能读取联合后的
容器，而且结构变化和恢复风险长期存在，因此不采用。

### 方案 C：改写菜单可用状态和制作数量

分别 Hook 建筑列表、图标判定、配方最大数量等入口，使用 mod 自己的材料合计强制覆盖结果，真实请求到达时再
建立联合。

优点是联合窗口短。缺点是 UI 显示与真实扣料会形成两套逻辑，需要维护易变的参数布局，还可能遗漏更早缓存，
并在高频预览路径引入额外计算，因此不采用。

## 选定架构

采用方案 A：**早期 pre-hook + 通用材料操作会话 + 单一原生资源联合**。

现有资源发现、同公会过滤、联合应用和按注入次数恢复的实现继续作为底层机制。本次只重构“何时请求联合、
何时复用、何时恢复”以及 Hook 清单和能力评估，不重写资源池。

### 通用材料操作定义

用纯值定义描述每类操作：

- 操作 ID：本轮为 `building` 和 `crafting`；
- 生命周期策略：显式结束或空闲超时；
- 早期获取入口：必须在原版首次材料资格计算前触发；
- 活动刷新入口：只延长现有会话，不创建已被暂停的会话；
- 结束入口：显式释放，或由空闲超时释放；
- Hook 阶段：pre 或 post；
- 能力要求：必需、可选，或同组至少一个可用；
- 诊断名称。

Hook 清单只负责声明 Palworld 版本相关的函数路径和事件语义。资源池和会话注册表不包含具体
`UPalUIBuildModel`、`UPalBuilderComponent` 或 `UPalUIConvertItemModel` 分支。

### 通用会话注册表

以固定大小的纯 C++ 状态表替换硬编码的 `buildingActive_`、`craftingActive_`：

- 每个操作保存当前世界代次、活动状态、暂停状态和空闲计时；
- `acquire` 只在世界代次匹配且操作未暂停时激活会话；
- `touch` 只刷新已经活动的会话，不隐式创建会话；
- `release` 结束指定会话；
- 活动会话总数从 0 变为 1 时请求建立联合；
- 活动会话总数从 1 变为 0 时请求恢复联合；
- 世界代次变化、关闭开关和卸载会原子地清空全部会话状态。

该状态表不保存 Unreal 指针，不进行动态对象发现。高频 Hook 中的 `touch` 是固定大小的 O(1) 状态写入。

### 建筑操作调用链

建筑会话使用显式生命周期：

1. `PalUIBuildModel:OnOpenMenu` pre-hook 是主要早期获取入口。联合必须在原函数生成或请求建筑可用状态前建立。
2. `PalUIInGameMainMenuBuildModel:Setup` pre-hook 作为菜单模型初始化入口和兼容性补充。
3. `PalUIBuildModel:GetBuildObjectDataArrayForUIDisplay` 等建筑列表入口只执行 `touch`，不重新发现或建立联合。
4. `PalBuilderComponent:IsExistsMaterialForBuildObject`、`PalUIBuildModel:StartBuildObject`、
   `PalUIBuildingModel:Setup` 和 `PalUIBuildingModel:BuildObject` 的 pre-hook 只确认现有会话与联合代次有效。
5. `PalBuilderComponent:ChangeMode` post-hook 继续读取 `IsInBuildingMode`；退出建造模式时释放建筑会话。
6. 已验证存在且语义明确的 `Dispose`/关闭入口作为额外释放路径；LoadMap、关闭开关和卸载仍是强制恢复兜底。

能力评估要求至少存在一个能在首次建筑资格计算前执行的必需入口，以及材料检查和真实建造入口。缺少任一必需
组时禁用建筑共享，而不是退回到晚期返回值覆盖。

### 制作操作调用链

制作会话使用空闲租约：

1. `PalUIConvertItemModel:Initialize` 从 post-hook 改为 pre-hook，并作为制作会话的主要获取入口。
2. `PalUIProductSettingModel:SelectRecipe`、`SetFocusedRecipe`、
   `CalcMaxProductableNum`、`PalUIConvertItemModel:CanStartProduction` 和 `StartProduction` 的 pre-hook
   只执行 `touch` 和代次检查。
3. 连续 1.5 秒没有制作活动且没有其他活动操作时，释放制作会话并恢复联合。
4. 若能确认安全的制作模型关闭入口，则它作为显式提前释放；空闲租约仍保留为漏失结束事件的兜底。

这样初始化、配方最大数量、开始按钮和真实生产请求都读取同一联合，而不会在每次配方刷新时追加和恢复数组。

### 单一联合与重叠操作

资源联合是所有材料操作共享的单例：

- 第一个活动会话建立联合；
- 后续建筑或制作会话只增加活动操作，不再次追加容器；
- 任一会话结束时，只要仍存在其他活动会话就保持联合；
- 最后一个会话结束时恢复一次；
- 联合有效时，`ensure_union` 先检查纯值的活动标志、世界代次和公会身份，直接返回，不调用
  `resolve_world_context`、对象名称查询、目录发现或数组追加。

## 数据流

### 正常打开建筑菜单

1. 原版调用 `OnOpenMenu`。
2. pre-hook 获取建筑会话。
3. 会话总数由 0 变为 1。
4. 复用已就绪目录，解析当次所需容器并建立一次联合。
5. 原版 `OnOpenMenu` 继续执行，建筑列表、材料数量与可用状态读取联合后的容器。
6. 后续列表刷新和放置预览只 `touch`。
7. 退出建造模式后释放会话；若没有制作会话，恢复联合。

### 正常打开制作界面

1. 原版调用 `PalUIConvertItemModel:Initialize`。
2. pre-hook 获取制作会话，并在需要时建立联合。
3. 原版初始化配方、最大制作数量和按钮状态。
4. 配方选择、数量变化和开始制作只刷新租约。
5. 空闲 1.5 秒后释放制作会话；若没有建筑会话，恢复联合。

### 目录尚未就绪

世界就绪后的 EngineTick 和空闲低频校准负责目录发现。菜单早期 Hook 不执行全局扫描或槽位扫描：

- 已有有效目录时建立联合；
- 目录不可用时，本次获取失败并保持原版行为，同时调度下一次安全 EngineTick 校准；
- 同一次菜单会话的高频 `touch` 不反复重试；
- 关闭并重新打开菜单后可以再次获取。

该策略优先保证帧时间和安全性。正常情况下，世界进入后的初始校准会在玩家打开菜单前完成。

## 性能与生命周期约束

- 共享关闭时不注册材料操作 Hook，不发现据点，不执行资源反射。
- 共享开启但没有活动材料会话时：
  - 结构 Hook 只设置调度标记；
  - 8 秒兜底校准只允许在空闲状态运行；
  - 校准只遍历管理器登记的据点与普通仓储，不读取物品槽位。
- 活动会话期间暂停 8 秒兜底校准，避免菜单停留期间周期性恢复和重建。
- 第一个会话只建立一次联合；高频入口只做 O(1) 的租约刷新和代次比较。
- 多个操作共享同一联合，最后一个结束后才恢复。
- 高频 Hook 不调用 `StaticFindObject`、`FindFirstOf`、`ProcessEvent`、对象名称解析、目录发现、数组追加、
  数组恢复或日志输出。
- 目录发现、首次联合、结构失效处理和最终恢复分别保留单次耗时日志。
- 若首次联合耗时异常，日志用于定位容器数量和具体阶段；不通过逐秒缓存或逐帧分摊重新引入常驻开销。

## 结构变化与失效策略

普通物品数量变化不会使目录失效，已联合的实时容器会由 Palworld 原生逻辑直接反映数量变化。

据点、存储模块或登记箱子结构在联合活动期间发生变化时：

1. 结构 Hook 只设置失效标记，不在 Hook 回调中扫描。
2. 下一个安全 EngineTick 恢复当前联合并清空活动操作会话。
3. 当前会话标记为暂停，后续高频 `touch` 不能重新建立联合。
4. EngineTick 在原生关系恢复后重新校准目录。
5. GUI 和日志提示重新打开建筑或制作菜单。
6. 玩家重新打开菜单产生新的 `acquire`，再基于新目录建立联合。

这种低频结构事件允许一次明确的恢复与校准成本，但不会在列表或预览调用中重建，也不会继续使用已经销毁的
容器句柄。

## 错误处理

- 角色安全门失败：保持原版行为，不注册对应材料 Hook。
- 必需 Hook 缺失：仅禁用对应操作能力；建筑和制作独立评估。
- 目录不可用：不建立部分联合，不覆盖原版结果，调度安全重试。
- 容器解析不完整：本次会话获取失败，保持原版行为。
- 联合追加失败：立即按本次恢复账本回滚；失败操作在本次菜单会话内暂停。
- 联合恢复失败：本世界禁用所有材料共享能力，避免在未知数组状态上继续修改。
- 世界代次、公会或权限变化：立即清空会话，恢复联合并清空目录。
- LoadMap 前置、关闭开关和卸载：先恢复联合，再注销 Hook。
- 不论何种失败，均不强制返回“可建造”“可制作”或“请求成功”。

## 纯 C++ 测试

新增或调整测试覆盖：

- 通用操作定义的必需/可选/同组至少一个 Hook 能力评估；
- 第一个 `acquire` 产生打开联合转换，重复 `acquire` 不重复打开；
- `touch` 只刷新已活动会话，不能恢复暂停或未获取的会话；
- 建筑与制作重叠时只打开一次，最后一个释放时才关闭；
- 制作空闲 1.5 秒到期，建筑显式会话不受制作空闲计时影响；
- 世界代次不匹配的 `acquire`、`touch` 和 `release` 无效；
- 结构失效会暂停当前会话并要求新的 `acquire`；
- 活动会话期间调度器不执行 8 秒校准；
- 关闭状态不需要材料 Hook、目录校准或联合；
- Hook 清单包含建筑菜单早期 pre-hook、制作初始化 pre-hook、资格检查和真实请求入口；
- 现有公会过滤、去重、稳定排序、联合幂等与按注入次数恢复测试继续通过。

静态检查继续禁止资源共享生产代码使用：

- `FindAllOf` 枚举据点存储、物品容器或多容器助手；
- 读取 `ItemSlotArray` 或 `StackCount` 计算共享预览；
- 在高频 Hook 中重建目录或覆写原版返回值。

## 构建与游戏内验收

构建验证：

```powershell
cmake --build --preset ninja-msvc-x64 --target format-check PalworldEditor PalworldEditorTests PalworldEditorBaseResourceSharingTests
ctest --test-dir build --output-on-failure
git diff --check
```

游戏内测试不得同时启用 IntegratedStorage、UBIM Lite 或其他修改相同材料请求路径的 mod。

### 原版建筑菜单

1. 本地据点没有材料、另一同公会已加载据点材料充足。
2. 打开原版建筑菜单，建筑图标在首次显示时即可选择。
3. 材料数量显示同公会合计。
4. 进入放置并完成建造，Palworld 原生逻辑从联合容器正确扣料。
5. 合计材料不足时图标保持不可用且不扣料。
6. 反复打开、切换分类和停留菜单 2–3 分钟，日志中没有重复目录发现或联合重建，帧率不出现周期性尖峰。

### 工作台与流水线

1. 本地据点没有材料、另一同公会已加载据点材料充足。
2. 打开工作台或流水线时，配方可用状态和最大制作量使用跨据点合计。
3. 选择配方、修改数量和开始制作不会重复建立联合。
4. 实际制作成功并由 Palworld 原生逻辑正确扣料。
5. 材料不足时不能开始且不扣料。

### 生命周期与安全

1. 建筑与制作会话重叠时只有一组联合建立/恢复日志。
2. 新建或拆除普通箱子、据点结构变化后，当前共享安全暂停；重新打开菜单后使用新目录。
3. 关闭共享、退出世界、重进存档和卸载均恢复原版行为且不崩溃。
4. 连续冷启动时，进入主界面前不执行资源反射。
5. 共享关闭时，工厂与建筑菜单性能和未加载资源功能时一致。

## 后续扩展契约

后续支持研究、修理或其他材料消耗场景时，只能：

1. 为该场景确认原版早期资格入口、真实请求入口和结束语义；
2. 添加新的操作 ID 与数据驱动 Hook 定义；
3. 增加独立能力评估、会话策略和测试；
4. 复用同一目录、联合和恢复核心。

不得为了扩展新场景引入永久联合、每帧/逐秒槽位扫描或通用返回值伪造。若某场景没有可验证的早期入口和安全
生命周期，则该能力保持不可用。

## 兼容性说明

该设计基于 Palworld 1.0.1 UHT dump 中已识别的 UFunction 名称。实施时必须再次核对每个函数的实际解析、
调用顺序和上下文类型；无法确认的入口标记为可选或禁用相应能力，不猜测参数内存布局。

本设计借鉴 Integrated Storage 对“菜单合计与真实扣料必须一致”的外部行为目标，但不复制其二进制实现，
也不依赖该 mod。PalSchema、Palworld 或 UE4SS 更新后，必须重新验证 Hook 路径、pre/post 时序、容器属性和
恢复行为。
