# PalworldEditor 1.6.5–1.6.7 安全修复与集成设计

## 目标

在保留三个既有功能分支提交历史的前提下，将被动技能分类、帕鲁属性编辑和爪钩枪无冷却集成到同一累计分支，
修复错误目标写入、破坏性默认值、不可逆冷却覆盖和潜在帧尖峰，并保持所有 Unreal 访问只发生在游戏线程。

## 全局约束

- 不缓存跨 EngineTick 的 `UObject*`、`UFunction*`、`FProperty*` 或结构内存地址。
- GUI 线程只提交标准库值请求；EngineTick 消费请求并执行 Unreal 访问。
- LoadMap 前清空请求并撤销写权限；后置回调只恢复读取能力和必要的按需重应用。
- 默认关闭的功能必须零扫描、零写入。
- 不增加逐帧空闲对象解析、全局 UObject 扫描或后台线程。
- 每项修改先写失败测试，再实现最小修复。

## 被动技能分类

保留运行时 `Rank` 与 `AddWorldTreePal` 分类来源、成功缓存和增量 EngineTick 任务。过滤接口改为返回
`const SkillOption*` 视图，避免下拉框每帧复制完整字符串。结果向量预留目录容量，目录顺序、搜索和排除语义
保持不变。分类反射仍采用每 Tick 软预算，不缓存 Unreal 句柄。

分类模型与增量任务继续作为纯 C++ 逻辑，可独立测试。GUI 只在下拉框打开时构造轻量指针视图。

## 帕鲁属性编辑

属性编辑新增纯值 `PalStatEditDraft`。目标首次可读或目标代次变化时从实际快照初始化；草稿生成请求时只携带
与原值不同的字段，未修改字段保持 `std::nullopt`。

属性请求使用单槽 latest-wins 提交器，避免无界积压。游戏线程执行前复用已锁定目标语义，同时验证世界代次、
目标代次、当前观察 GUID 和 UObject 有效性。`de49fff` 的“属性请求触发当前帕鲁解析”行为保留。

网关先解析全部待写属性和所需函数，再执行任何写入。属性缺失、亲密度阈值查询失败或目标失效时零写入。
写入后重读并验证请求字段；失败时恢复修改前快照并报告结构化结果。普通个体值输入上限为 100。

## 爪钩枪无冷却

爪钩功能从资源共享配置命名空间中拆出为独立纯值服务。服务只表达期望状态、按世界代次建立的覆盖账本和
应用/恢复决策；Unreal 网关负责定位已确认的爪钩对象、读取和写入 `CoolDownTime`。

默认关闭且没有活动账本时，启动与世界就绪均为 no-op。开启时仅覆盖通过爪钩识别谓词的对象并保存各自原值；
关闭、LoadMap 前和卸载时只恢复本 mod 实际覆盖的对象，不使用硬编码 8 秒。账本仅保存对象全名、原始浮点值和
世界代次，不保存 Unreal 指针。

如果当前版本无法通过稳定类型、Raw ID 或对象路径确认爪钩目标，操作失败关闭，不得退化为修改所有
`PalWeaponBase`。

## 集成顺序

1. 合并并修复被动技能分类，版本为 1.6.5。
2. 合并属性编辑并解决 `dllmain.cpp` 冲突，版本为 1.6.6。
3. 合并爪钩无冷却并解决配置和生命周期冲突，版本为 1.6.7。
4. 在累计分支运行格式、构建、CTest 和补丁检查；游戏内验证作为发布前必要步骤。

## 错误处理

- 所有运行时写操作返回结构化状态和用户可读消息。
- 不支持的反射布局必须零写入并明确报告。
- 部分写入必须回滚；回滚失败时禁用本世界后续同类写操作。
- 默认关闭、目标不可用和世界切换期间不得执行恢复之外的写入。

## 测试

- 被动过滤验证零值拷贝视图、顺序、类别、搜索和排除。
- 属性草稿验证安全初始化、差量请求、目标不匹配拒绝和 latest-wins。
- 属性事务验证预检失败零写入、写后验证和回滚决策。
- 爪钩服务验证默认关闭零调用、只覆盖确认目标、幂等开启、原值恢复、LoadMap 和卸载恢复。
- 纯 C++ 测试不声称覆盖 Unreal ABI；最终仍需游戏内验证对象识别、保存效果和帧时间。
