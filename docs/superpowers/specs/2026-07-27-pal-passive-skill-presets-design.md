# Pal 被动技能预设设计

日期：2026-07-27

目标版本：PalworldEditor 1.6.4

适用游戏：Palworld 1.0.1

## 目标

在现有 Pal 被动技能编辑区增加预设下拉框和独立的“应用预设”按钮。用户选择预设后不会立即修改；只有点击
“应用预设”才提交一次完整的被动技能组替换请求。

首批预设：

| 显示名 | 最终被动技能 | Palworld Raw ID |
|---|---|---|
| 工作毕业1 | 恶魔之手、卓绝记忆、吸血鬼、工匠精神 | `WorldTree_CraftSpeed`、`CraftSpeed_up3`、`Vampire`、`CraftSpeed_up2` |
| 工作毕业2 | 恶魔之手、卓绝记忆、工匠精神、社畜 | `WorldTree_CraftSpeed`、`CraftSpeed_up3`、`CraftSpeed_up2`、`PAL_CorporateSlave` |

Raw ID 以 Palworld 1.0.1 数据为准，并与
[PalworldSaveTools 的工作速度预设](https://github.com/deafdudecomputers/PalworldSaveTools/blob/4bc353e5c4ec14f1bfa794ccb30859500d6c8aae/src/data/configs/passive_loadouts.json)
交叉核对。预设写入不依赖中文名称反查，因此切换游戏语言不影响应用结果。

## 范围

本次包含：

- 两个内置 C++ 被动技能预设；
- 可扩展的预设定义目录；
- 下拉选择、预设内容预览和独立应用按钮；
- 单次批量请求、目标校验、差量写入、重读验证和完整回滚；
- 纯 C++ 自动测试与既有技能编辑回归。

本次不包含：

- 外部配置文件或游戏内自定义预设；
- 主动技能、伙伴技能、属性或工作适应性预设；
- 批量编辑多个 Pal；
- 新增 Hook、后台线程、空闲扫描或定时刷新。

## 预设目录

新增自包含的 `inc/skills/passive_skill_presets.hpp`。预设使用只读固定大小数据：

```cpp
struct PassiveSkillPreset {
    std::string_view id;
    std::string_view displayName;
    std::array<std::string_view, 4> passiveIds;
};
```

头文件提供只读 `std::span<const PassiveSkillPreset>` 访问器。UI 和测试只依赖该接口；增加预设时只需在定义数组
中追加一项，不修改渲染和执行状态机。每个预设必须满足：

- 稳定且唯一的内部 ID；
- 非空显示名；
- 恰好四个非空、互不重复的 Raw ID。

## UI

预设控件位于现有被动技能列表上方：

```text
词条预设：[请选择预设 ▼] [应用预设]
预设内容：恶魔之手、卓绝记忆、吸血鬼、工匠精神
```

行为：

1. 下拉框只列出预设显示名。
2. 选中后，在下方按预设顺序显示四个技能；优先使用当前游戏语言的技能目录标签，找不到时回退 Raw ID。
3. 选中预设本身不产生请求。
4. 未选中预设、目标不可编辑、世界切换中、目录未就绪或已有请求待处理时禁用“应用预设”。
5. 点击“应用预设”后关闭当前单技能新增/替换选择状态，并向既有线程安全 FIFO 推入一个请求。
6. 切换已确认目标或进入新世界时，清空 GUI 中的预设选择。
7. 执行结果继续使用既有“结果”区域显示，不增加常驻日志。

特殊的世界树技能可能不会出现在普通可分配目录中。目录缺失只影响本地化预览，不阻止使用已核实 Raw ID
应用预设。

## 请求模型与目标安全

扩展 `SkillEditOperation`，加入整组被动技能替换操作；`SkillEditRequest` 增加批量目标 Raw ID 列表。请求仍携带：

- 提交时的目标代次；
- 提交时的世界代次；
- 不包含 `UObject*` 的纯值目标信息。

GUI 不执行反射。EngineTick 消费请求时沿用现有流程：

1. 检查世界代次；
2. 重新解析数字键当前高亮、下一次按 E 会召唤的队伍 Pal；
3. 检查锁定目标 GUID 和目标代次；
4. 只在校验成功后把当帧非拥有对象句柄交给技能网关；
5. 执行结束后只发布标准库快照。

数字键切换、LoadMap、解析失败和待处理请求的规则与现有单技能编辑一致。

## 差量替换与回滚

批量服务先读取原始被动技能列表并验证预设。被动技能按无序集合处理，最终必须恰好等于预设四项。

正常执行：

1. 原始列表已与预设相同：不调用任何写入函数，返回成功。
2. 删除原始列表中不属于预设的技能。
3. 添加预设中尚未存在的技能。
4. 重读实际列表。
5. 实际列表与预设集合相同：返回成功。

失败回滚：

1. 读取失败后的实际列表。
2. 删除实际列表中不属于原始列表的技能。
3. 添加原始列表中缺失的技能。
4. 再次重读。
5. 与原始集合相同则返回 `rolledBack`，否则返回 `rollbackFailed`。

网关调用的布尔返回值只作为诊断线索，最终状态始终以重读结果为准。差量算法不为了调整显示顺序而删除并重加
相同技能；被动技能顺序不参与成功判断。

## 性能约束

该功能必须满足以下结构性约束：

- 未点击按钮时不增加任何 EngineTick、对象解析、反射、目录扫描或后台任务；
- 不注册新的 UFunction Hook；
- 预设目录是编译期固定小数组；
- 下拉框只遍历预设数量，不遍历游戏对象；
- 应用请求只解析一次当前目标；
- 已是目标预设时为零写入；
- 差量执行最多删除四项、添加四项，并进行有界重读；
- 不刷新主动/被动技能目录；
- 不调用 `FindAllOf`；
- 不跨帧缓存 `UObject*` 或 Unreal 数组地址；
- 不为每个词条输出日志。

选择单 Tick 有界执行，而不是跨 Tick 分步写入。分步方案会让 Pal 在多个帧内处于半完成状态，并要求重复目标
解析或跨帧保存不安全的对象句柄。最终帧时间仍需在 Palworld 内测量，但该设计不会产生常驻帧率开销。

## 错误处理

- 预设定义非法：领域服务在写入前拒绝。
- 目标、世界或目标代次失效：沿用现有拒绝结果，不做写入。
- 游戏拒绝部分删除或添加：重读实际状态后进入回滚。
- 回滚成功：显示已恢复原词条。
- 回滚失败：显示实际重读状态和明确错误；不继续自动重试。
- LoadMap 前：既有生命周期会清空尚未消费的 FIFO 请求；单 Tick 执行不留下跨世界事务。

## 测试

纯 C++ 测试至少覆盖：

1. 两个预设的显示名、顺序和精确 Raw ID；
2. 所有内置预设的内部 ID 唯一、四项非空且互不重复；
3. 选定预设生成一个批量请求，而不是四个单技能请求；
4. 已经匹配预设时零写入；
5. 完全不同的四词条成功替换；
6. 与预设部分重合时只执行必要删除和添加；
7. 中途写入失败后恢复完整原列表；
8. 回滚失败返回 `rollbackFailed`；
9. 空、重复或不是四项的批量列表在写入前被拒绝；
10. 错误目标、错误目标代次和错误世界代次不执行写入；
11. 现有单技能新增、替换、删除和主动技能测试保持通过。

游戏内验收：

- 选择预设不会立即修改；
- 点击应用后四个被动技能成为所选预设；
- 中文及其他游戏语言下均能正确写入并显示当前语言名称；
- 已是目标预设时重复应用不改变状态；
- 数字键切换、退出世界和重进存档仍遵守现有目标安全门；
- 未操作预设时帧时间与修改前一致，点击应用时无可感知持续掉帧。
